How to enable more trust in your AI agents

Can your AI agent be trusted beyond a demo? How to scale beyond a demo?

In this blog post I wanted to share how you could add more trust to your AI agents.

In today’s world AI agents are everywhere. But the most important thing and the most important question to ask yourself, can I trust the AI agents that I am using or building? Will it follow my instructions well and will the agent do the thing that I’ve asked it to do? And that too, how well?

Maybe you have just built a demo and now you’re looking to deploy this AI agent and prior to deployment, you want to test it. Will the agent scale to hundreds and thousands of users? At the same time how can you be sure of it?

As part of this blog post, I want to share some very practical tips on how to best test your agents prior to deployment and how to build them to scale.

We will be talking about evals, but I will also be mentioning about real-time monitoring more commonly referred to as agent guardrails.

The blog post is framework agnostic. The methods and the ideas that I share here can be are applicable to any AI agent ecosystem - both for multi and single agent systems.

The tool of choice for me has really been Promptfoo.

To test an AI agent properly, you need both deterministic and non-deterministic evaluations. Deterministic - for more straightforward expectations where you know exactly what to expect. Example, “did the agent call the Google search tool when I asked it to search about how to best use Claude Code?” Or if you asked what is 2 + 3 and you expect the answer to be 5. These are meant to test close ended questions.

And think of non-deterministic evals as for more open-ended questions. Example, the LLM writes a description of an image and you want to check the quality of it. These non-deterministic evals are also referred to as LLM as a judge. What LLM as a judge really is, is that based off a system prompt, it is returning a score on the output of your agent. Example, “for a customer service agent, did the agent answer the question properly or not?” These evaluations are more broad compared to the other deterministic half.

1 Why Promptfoo?

So first question you might ask is why have I chosen PromptFoo as my vessel for agent evals? The answer is simple. It has support for a wide variety of frameworks and also allows for customization. The UI is clean, and it is really easy to set up.

It lets me answer all the questions that I may have during the build phase below:

  • Is system prompt A better than system prompt B?
  • What is the average latency from question to response?
  • How accurate is my agent?
  • Which model to go for? How well does GPT-4.1 perform against Claude Sonnet 4.5 on this task?
  • Can I merge the two tools that I’ve added to the agent?
  • How well does the agent perform on these variety of different 25 tasks? What’s the average score?

What about during deployment?

  • Is the agent continuing to follow the pattern that I’ve asked it to do or does it stray off the path?
  • Any PII leakage that I should be aware of? Or any NFSW content?
  • Are the users trying to steal my system prompt and steer the agent in a wrong direction?
  • Any malicious users I should be aware of?

In this code first deep dive, I will help answer all the questions above. We will first focus on the build phase and then move on to the deployment phase. Dare I say, it is not so much the tool but the systematic thinking that we apply, which is way more useful. The system of steps that I will follow in this blog post can really help your agents scale well beyond the demo. With that being said, let’s get started.

2 The build phase

This is the phase where you’re building the AI agent. This is the phase where you’re experimenting. This is also the phase where you’re testing. To engineers and data scientists, this is not a new concept. Engineers might more commonly refer to as integration and unit tests - and data scientists more commonly know this phase as model training phase where you are constantly checking the metrics on the “validation” split.

We need to apply the same concepts and mindset to AI agents building phase.

To start, you need a list of metrics that matter to you - and please refrain from general purpose off the shelf metrics that are available today such as fluency, factuality, safety and coherence!:. At the cost of sounding a bit dramatic, please throw these metrics in the bin. We need metrics that are more custom, metrics that can be trusted.
