1 Introduction

Andrej Karpathy just released a single Python file — gpt3_micro.py — that trains and inferences a GPT in 243 lines of pure, dependency-free Python. No PyTorch, no NumPy, no CUDA. Just three standard library imports:

import os       # os.path.exists
import math     # math.log, math.exp
import random   # random.seed, random.choices, random.gauss, random.shuffle

The claim at the top of the file is bold:

“This file is the complete algorithm. Everything else is just efficiency.”

That’s a profound pedagogical statement. What Karpathy is saying is that everything PyTorch, CUDA, FlashAttention, mixed precision training, and distributed computing do is make this same algorithm run faster. The algorithm itself fits in 243 lines.

I wanted to understand every single line. So I broke the file apart, traced through each section, and wrote this post. Let’s go.

2 The Dataset

The file downloads a dataset of ~32,000 baby names and loads them as a list of strings:

if not os.path.exists('input.txt'):
    import urllib.request
    urllib.request.urlretrieve(
        'https://raw.githubusercontent.com/karpathy/makemore/refs/heads/master/names.txt',
        'input.txt'
    )

docs = [l.strip() for l in open('input.txt').read().strip().split('\n') if l.strip()]
random.shuffle(docs)
num docs: 32033
first 10 docs: ['yuheng', 'diondre', 'xavien', 'jori', 'juanluis', ...]

Each name is a “document.” The model will learn to generate new names character by character.

3 The Tokenizer

The tokenizer is the simplest possible kind — character-level. Each unique character becomes a token, plus one special <BOS> (Beginning of Sequence) token:

chars = ['<BOS>'] + sorted(set(''.join(docs)))
vocab_size = len(chars)  # 27

stoi = {ch: i for i, ch in enumerate(chars)}  # string -> integer
itos = {i: ch for i, ch in enumerate(chars)}  # integer -> string
BOS = stoi['<BOS>']  # = 0
chars: ['<BOS>', 'a', 'b', 'c', ..., 'z']
stoi: {'<BOS>': 0, 'a': 1, 'b': 2, 'c': 3, 'd': 4, ...}
itos: {0: '<BOS>', 1: 'a', 2: 'b', 3: 'c', 4: 'd', ...}

That’s all a tokenizer is — two lookup dictionaries. One to encode strings into integers, one to decode integers back to strings. Modern LLMs use BPE (Byte-Pair Encoding) with vocabularies of 50k-200k tokens, but the principle is identical.

4 The Operations

Before we look at the model itself, let’s understand the three mathematical building blocks it uses.

4.1 Linear (Matrix-Vector Multiply)

def linear(x, w):
    return [sum(wi * xi for wi, xi in zip(wo, x)) for wo in w]

This is just W @ x — matrix multiplication. w is a matrix (list of lists) with shape [nout][nin], x is a vector of length nin, and the output is a vector of length nout. For each row in w, compute the dot product with x. This is the core building block of neural networks — a learned linear transformation.

4.2 Softmax

def softmax(logits):
    max_val = max(val.data for val in logits)
    exps = [(val - max_val).exp() for val in logits]
    total = sum(exps)
    return [e / total for e in exps]

Softmax takes arbitrary numbers (logits) and converts them into a probability distribution — all values between 0 and 1, summing to 1. The higher the input, the higher the probability. The subtraction of max_val is a numerical stability trick that doesn’t change the output (the ratios stay the same), but prevents exp(huge_number) from overflowing.

For example, logits [2, 5, 1] with max = 5:

  • exp(2-5) = exp(-3) = 0.05
  • exp(5-5) = exp(0) = 1.0 — the biggest input gets the biggest probability
  • exp(1-5) = exp(-4) = 0.02
  • After normalizing: [0.05, 0.93, 0.02]

4.3 RMSNorm

def rmsnorm(x):
    ms = sum(xi * xi for xi in x) / len(x)
    scale = (ms + 1e-5) ** -0.5
    return [xi * scale for xi in x]

Root Mean Square Normalization. It divides every element by the RMS (root mean square) of the vector, keeping values roughly in [-1, 1]. This prevents numbers from exploding or vanishing as they flow through layers. It’s a simpler alternative to LayerNorm — just scaling, no mean subtraction.

5 Parameter Initialization

Before the model can do anything, we need to create its weight matrices — these are the learnable parameters that start as random numbers and get adjusted during training.

n_embd = 16      # embedding dimension
n_head = 4       # number of attention heads
n_layer = 1      # number of transformer layers
block_size = 8   # maximum sequence length (context window)
head_dim = n_embd // n_head  # = 4

matrix = lambda nout, nin, std=0.02: [
    [Value(random.gauss(0, std)) for _ in range(nin)]
    for _ in range(nout)
]

matrix(nout, nin) creates a list-of-lists with nout rows and nin columns, filled with small random numbers (Gaussian, mean=0, std=0.02). Each number is wrapped in a Value object for autograd (more on that later).

The state dict holds every weight matrix in the model:

state_dict = {
    'wte':     matrix(vocab_size, n_embd),   # [27][16]  Token embeddings
    'wpe':     matrix(block_size, n_embd),   # [8][16]   Position embeddings
    'lm_head': matrix(vocab_size, n_embd),   # [27][16]  Final output layer
}

Plus per-layer attention and MLP weights:

layer0.attn_wq            -> [16][16]   Query projection
layer0.attn_wk            -> [16][16]   Key projection
layer0.attn_wv            -> [16][16]   Value projection
layer0.attn_wo            -> [16][16]   Output projection (init to zero!)
layer0.mlp_fc1            -> [64][16]   MLP expand:   16 → 64
layer0.mlp_fc2            -> [16][64]   MLP compress: 64 → 16 (init to zero!)

Total parameters: 4,064

Notice attn_wo and mlp_fc2 are initialized to zero (std=0). This is intentional — at the start of training, these zero matrices mean the attention and MLP blocks output nothing, so the residual connections just pass the input through unchanged. The model starts as essentially an identity function and gradually learns to do useful transformations.

6 The GPT Forward Pass

This is the heart of the file. The gpt() function processes one token at a time and returns logits (scores) for what comes next.

6.1 Step 1: Embedding

def gpt(token_id, pos_id, keys, values):
    tok_emb = state_dict['wte'][token_id]  # look up token embedding → [16]
    pos_emb = state_dict['wpe'][pos_id]    # look up position embedding → [16]
    x = [t + p for t, p in zip(tok_emb, pos_emb)]  # add them → [16]
    x = rmsnorm(x)

Each token becomes a 16-dimensional vector that encodes both what the token is and where it is in the sequence. The token embedding (wte) captures identity (“this is the letter ‘a’”), the position embedding (wpe) captures location (“this is position 3”).

6.2 Step 2: Attention

    for li in range(n_layer):
        x_residual = x
        x = rmsnorm(x)
        q = linear(x, state_dict[f'layer{li}.attn_wq'])  # query
        k = linear(x, state_dict[f'layer{li}.attn_wk'])  # key
        v = linear(x, state_dict[f'layer{li}.attn_wv'])  # value
        keys[li].append(k)
        values[li].append(v)

The input x gets projected into three vectors: Query (“what am I looking for?”), Key (“what do I contain?”), and Value (“what information do I offer?”).

The K and V vectors get cached. This is the KV cache — and understanding it is key to understanding autoregressive generation. Let me trace through processing the name “cat”:

Processing BOS (pos 0):  cache = [K_bos]                    → attends to 1 token
Processing 'c' (pos 1):  cache = [K_bos, K_c]               → attends to 2 tokens
Processing 'a' (pos 2):  cache = [K_bos, K_c, K_a]          → attends to 3 tokens
Processing 't' (pos 3):  cache = [K_bos, K_c, K_a, K_t]     → attends to 4 tokens

Each token can only look backward (including itself). Never forward. This is what makes it autoregressive — each token predicts the next one based only on what came before.

Why cache K and V but not Q? Because Q is only used by the current token. But K and V are needed by every future token that wants to attend to this position. Caching avoids recomputing them.

6.3 Step 3: Multi-Head Attention

        x_attn = []
        for h in range(n_head):
            hs = h * head_dim
            q_h = q[hs:hs+head_dim]
            k_h = [ki[hs:hs+head_dim] for ki in keys[li]]
            v_h = [vi[hs:hs+head_dim] for vi in values[li]]
            attn_logits = [sum(q_h[j] * k_h[t][j] for j in range(head_dim)) / head_dim**0.5
                           for t in range(len(k_h))]
            attn_weights = softmax(attn_logits)
            head_out = [sum(attn_weights[t] * v_h[t][j] for t in range(len(v_h)))
                        for j in range(head_dim)]
            x_attn.extend(head_out)

The 16-dim Q, K, V get split into 4 heads of 4 dimensions each. Each head independently:

  1. Computes dot products between its Q and all cached K’s (scaled by 1/√head_dim)
  2. Applies softmax to get attention weights (probabilities over positions)
  3. Takes a weighted sum of the V’s using those weights

The 4 head outputs get concatenated back to [16], projected through attn_wo, and added to the residual:

        x = linear(x_attn, state_dict[f'layer{li}.attn_wo'])
        x = [a + b for a, b in zip(x, x_residual)]  # residual connection

6.4 Step 4: MLP Block

        x_residual = x
        x = rmsnorm(x)
        x = linear(x, state_dict[f'layer{li}.mlp_fc1'])  # [16] → [64]
        x = [xi.relu() ** 2 for xi in x]                  # ReLU² activation
        x = linear(x, state_dict[f'layer{li}.mlp_fc2'])  # [64] → [16]
        x = [a + b for a, b in zip(x, x_residual)]        # residual connection

The MLP expands from 16 to 64 dimensions (4x), applies a nonlinearity (ReLU²), then compresses back to 16. The wider hidden layer gives the network more room to transform features. The residual connection adds the output back to the input.

6.5 Step 5: Output

    logits = linear(x, state_dict['lm_head'])  # [16] → [27]
    return logits

The final linear layer projects from embedding space (16) back to vocabulary size (27), giving one score per possible next token.

6.6 Shape Trace Summary

Input:    token_id (scalar)
Embed:    tok_emb[16] + pos_emb[16] → x[16]
Norm:     rmsnorm → x[16]
Attn:     Q[16], K[16], V[16] → 4 heads of [4] → concat [16] → attn_wo → [16] + residual
MLP:      [16] → fc1 → [64] → ReLU² → fc2 → [16] + residual
Output:   lm_head → logits[27]

7 Training

7.1 The Loss Function

for step in range(num_steps):
    doc = docs[step % len(docs)]
    tokens = [BOS] + [stoi[ch] for ch in doc] + [BOS]
    n = min(block_size, len(tokens) - 1)

    keys, values = [[] for _ in range(n_layer)], [[] for _ in range(n_layer)]
    losses = []
    for pos_id in range(n):
        token_id, target_id = tokens[pos_id], tokens[pos_id + 1]
        logits = gpt(token_id, pos_id, keys, values)
        probs = softmax(logits)
        loss_t = -probs[target_id].log()
        losses.append(loss_t)

    loss = (1 / n) * sum(losses)  # May yours be low.

Each training step picks one name, wraps it in BOS tokens on both sides, and processes it token by token. At each position, the model predicts the next token, and the loss is the negative log probability of the correct answer. If the model assigns probability 1.0 to the right token, the loss is 0. If it assigns probability close to 0, the loss is huge.

The initial loss is ~3.30, which is log(27) — the loss you get from uniform random guessing across 27 tokens.

7.2 Backward Pass

    loss.backward()

One line. But this is where the autograd engine does its magic — it walks the entire computation graph backward, applying the chain rule at every node, and fills in .grad for every parameter. We’ll cover the Value class that makes this work in detail below.

7.3 Adam Optimizer

    lr_t = learning_rate * (1 - step / num_steps)
    for i, p in enumerate(params):
        m[i] = beta1 * m[i] + (1 - beta1) * p.grad
        v[i] = beta2 * v[i] + (1 - beta2) * p.grad ** 2
        m_hat = m[i] / (1 - beta1 ** (step + 1))
        v_hat = v[i] / (1 - beta2 ** (step + 1))
        p.data -= lr_t * m_hat / (v_hat ** 0.5 + eps_adam)
        p.grad = 0

Adam maintains two buffers per parameter:

  • m — running average of gradients (momentum, first moment)
  • v — running average of squared gradients (velocity, second moment)

The bias correction (m_hat, v_hat) compensates for the fact that m and v start at zero. The actual update divides momentum by the square root of velocity — parameters with consistent gradients take bigger steps, parameters with noisy gradients take smaller steps. The learning rate decays linearly from 1e-2 to 0 over training.

After 500 steps, the loss drops from ~3.30 → ~2.05 — meaningfully better than random.

8 Inference

temperature = 0.6
for sample_idx in range(20):
    keys, values = [[] for _ in range(n_layer)], [[] for _ in range(n_layer)]
    token_id = BOS
    for pos_id in range(block_size):
        logits = gpt(token_id, pos_id, keys, values)
        probs = softmax([l / temperature for l in logits])
        token_id = random.choices(range(vocab_size), weights=[p.data for p in probs])[0]
        if token_id == BOS:
            break
        print(itos[token_id], end="")

Generation starts with BOS, feeds each predicted token back as the next input, and stops when the model predicts BOS again (end of name). Temperature controls creativity — dividing logits by a small temperature (0.6) makes the distribution sharper (more confident picks), while temperature 1.0 gives the raw probabilities.

After training for 500 steps, the model generates:

hannh, tadas, akabho, kentie, anma, kela, azihei, madari,
tanas, caedan, torinn, meylee, adeyn, don, nadin, selran,
selin, alia, silin

Some of these genuinely pass as real names — “alia”, “selin”, “nadin”, “don”. Others are plausible but invented — “meylee”, “torinn”, “caedan”. Not bad for 4,064 parameters and 500 steps of pure scalar Python.

10 Conclusion

What makes this file remarkable isn’t just that it’s small — it’s that nothing is missing. This is the complete algorithm behind GPT. Every other piece of infrastructure in modern LLM training — PyTorch, CUDA kernels, FlashAttention, distributed training, mixed precision, gradient checkpointing — exists to make this exact algorithm run faster on bigger data with more parameters.

Karpathy’s gift is making that visible. When you strip away all the efficiency machinery, what remains is:

  1. A tokenizer (two dictionaries)
  2. An autograd engine (the chain rule, applied recursively)
  3. A transformer (attention + MLP with residual connections)
  4. An optimizer (Adam, four lines)
  5. A sampling loop (temperature-scaled softmax)

That’s it. That’s the whole thing.
